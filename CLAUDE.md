# Pixel Vibe

A retro arcade rhythm shooter that plays in the browser (and installs to the phone home screen). Old-school Galaga-style pixel graphics: your ship's shots are the drums, and other things (shield, pickups, enemies) each trigger different instrument sounds, so playing the game plays the music.

This is a brand-new project, separate from GabLab (`C:\Mikes Stuff\call-recorder`) and ProfilePilot (`C:\Mikes Stuff\ProfilePilot`). Do not touch those folders, their repos or their Firebase/Cloudflare accounts.

## Decisions so far
- **Plain HTML + vanilla JS + `<canvas>` + Web Audio.** No game engine. Godot is installed on this PC but was judged not worth it for a rhythm game (heavy web build, worse audio latency, nothing here needs physics or 3D).
- **Timing is everything.** Schedule sounds and judge hits against `AudioContext.currentTime`, not `setTimeout` or frame counts. Include a latency calibration screen (tap along to a beat) because Bluetooth and phone audio add delay. Never let frame-rate hiccups move the music.
- **Pixel look:** low-res canvas (e.g. 224x288 or 320x180) scaled up with `image-rendering: pixelated`, chunky sprites drawn in code or small PNGs, limited palette, CRT/scanline option is a nice extra.
- **Sound:** real recorded samples, not synthesis (the user wants it to sound really good). `audio/` holds TR-808/707 drums and 26 FluidR3 instruments; sources and licenses are in `audio/CREDITS.md`. Only use samples whose license allows it (the TR-909 set was rejected). Lots of instruments are wanted because ships will each have their own sounds; `LOADOUT` in `js/audio.js` picks them. Keep one shared master clock and a BPM so everything lands on the grid.
- **Game screen (v0.1.0):** three cannons (drums, bass, vibraphone) fire on their own notes; three piano keys under them (each the colour of its shield, no icons) raise a shield over each cannon and play a chord tone on the player's own big layered synth (two detuned saws, synth brass, a saw an octave down, filter sweep, dotted-8th echo); the keys are what the player controls, so their sound matters most; drag above a cannon to aim it. Headless check script: `check.mjs` pattern (Node http server + CDP at 390x844).
- **Gameplay (v0.4.0):** cannons stand on foundations of tiny 2px blocks; enemy and boss shots only chip blocks (never the cannons). A cannon falls below 30% blocks and its instrument is muted out of the song; all three down = game over. A level is 3 rounds: 45 s of enemy ships (2x-size sprites, 20 HP, fly in Galaga-style, park in slots, fire on the beat; a top bar shows time to the boss), then a boss (stationary, three ports above the three cannons). Bosses in `BOSSES`: saucer 400 HP, crab 550, mothership 700, patterns getting busier. Each boss times its shots to land on 16th steps, so blocking them with the keys plays the lead rhythm; positions come from the audio clock. Surviving cannons get their foundations rebuilt after each boss. Beating boss 3 = LEVEL CLEAR. Shields run on energy (drain 1.6 s, refill 2.5 s). Tuning constants sit at the top of `js/game.js`; `__pv.skipToBoss()` and `__pv.damageBoss(hp)` exist for headless checks.
- **Pause and exit (v0.7.0):** II button (and Esc, and leaving the app) opens PAUSED with Resume / Restart / Quit to title. X buttons on the title, pause and game screens call window.close(). Browsers only allow that while the page has ONE history entry, so never use history.pushState (v0.5 did, for a Back-opens-pause feature, which is why X failed). If close is refused (iPhone home-screen apps), X falls back to the title. The user does not want a "swipe the app away" message.
- **Always latest:** `sw.js` fetches code with `cache: no-store` (network first, cache only when offline), registers with `updateViaCache: none`, and the page calls `reg.update()` on every return. On `controllerchange` the page reloads at the title, or at the next Quit if a game is running. Samples stay cache-first (rename a sample if its content changes).
- **v0.6.0 changes:** aim assist (as of v0.7.0 cannons with no target auto-lock the target nearest where they point, anywhere in range, preferring targets other cannons do not have; dragging within 0.6 rad of a target locks that cannon on; it tracks it and re-locks the next target near where it points; shots home gently). Each boss repeats one 4-shot motif per bar (`motif` in `BOSSES`), shots are 24 px long and count as blocked if the shield is up any time the bolt is between the dome top and the blocks (about 0.25 s, centred on the beat). Bosses are beaten by destroying 12 big coloured blocks under the hull (`blockHp` per boss); the hull soaks shots.
- **v0.8.0:** touching anywhere above the keys aims ALL cannons there (a touch within 22 px of a ship or boss block locks all three onto it; empty space holds the aim 1.5 s, then they auto-aim again). Player shots are drawn as little waveforms per instrument (`WAVES`) that swell with the live mix; an AnalyserNode on the master feeds a 24-bar EQ meter behind the action. Enemies emit silent sound-wave ripples when they drop bombs. Start stays on LOADING until sounds load AND the update check finishes (`ensureLatest`), because a launch-time update reload used to land after the first Start tap ("false start").
- **v0.9.0:** auto-aim is OFF (user asked): cannons only follow a target the player touched. Enemies fire from the music scheduler (`music.onStep` -> `scheduleEnemies`) on their own rhythm (`ENEMY_RHYTHMS`) and each plays a high chord-tone note on kalimba / marimba / music box / steel drums (`LOADOUT.enemies`); their bombs are drawn as sound-wave arcs. Bosses play the song melody (`melody` in `BOSSES`: two bars of four notes + rest, each note [step, cannon, length]); each note is a bolt as long as the note, cut into 3 px slices that are absorbed only while that key is held (Guitar Hero style), with 60 ms release grace. Shield energy now lasts 2.5 s held.
- **Controls:** touch first (drag to move, tap/hold to fire), keyboard second.
- **Hosting:** GitHub Pages (live at https://spacepanda99.github.io/pixel-vibe/), installable since v0.2.0 (`manifest.webmanifest`, `icons/`, `sw.js`; bump `VERSION` in `sw.js` with every `?v=` bump), same pattern as GabLab (static files, `?v=` cache-busting on scripts, a version number in the footer, a service worker for install/offline). Repo: `spacepanda99/pixel-vibe` (public, so free Pages works), created 2026-10-18.

## Working rules (from the user)

- Never open the Browser/preview pane. Verify with headless Chrome over CDP (the `chrome.exe` at `C:\Program Files\Google\Chrome\Application\`), screenshots at phone width (360-412 px), and `node --check`. Never kill all `chrome.exe`: the user's own browser runs here.
- There are no real phones to test on from here, so say plainly what was and wasn't tested.
- Ask before any paid API call (even a few cents) and before creating any cloud project or GitHub repo.
- Commit after meaningful chunks of work. End commit messages with the attribution line from the session reminder.
- The PC is a 2-core, 4 GB RAM VM with no GPU and about 13 GB free disk. Headless WebGL is slow (about 2 fps), so prefer 2D canvas and keep test runs short.
- Shell notes: shell heredocs break on apostrophes, so write files with the file tool or a small `.cjs` patch script.
- Brand/art direction is open: ask the user for colours and the feel they want before polishing visuals.
